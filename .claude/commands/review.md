コードレビューを実施してください。

## 引数
$ARGUMENTS にレビュー対象が指定されます。未指定の場合はgitの差分を対象にします。

## レビュー対象の特定

### 引数ありの場合
- ファイルパスが指定された場合: そのファイルをレビュー
- PR番号が指定された場合: `gh pr diff $ARGUMENTS` で差分を取得してレビュー
- 「全体」「all」等の場合: プロジェクト全体をレビュー

### 引数なしの場合
- `git diff` で未コミットの差分をレビュー
- 差分がない場合は `git diff main...HEAD` で現在のブランチの全変更をレビュー

## チェック項目

### セキュリティ
- [ ] `as any` による型安全性の喪失がないか
- [ ] ハードコードされた認証情報（APIキー、パスワード等）がないか
- [ ] SQLインジェクションの可能性（`bind()` を使用しているか）
- [ ] パスワードやトークンが暗号的に安全な方法で生成されているか

### 自動生成ファイルの保護
- [ ] 自動生成コメント付きファイルを直接編集していないか
- [ ] seed定義の変更後に `sampleapp local generate` が実行されているか

### コード品質
- [ ] `#[allow(dead_code)]` や `// @ts-ignore` 等の抑制コメントが不要に追加されていないか
- [ ] TODO/FIXMEコメントが新たに追加されていないか（追加する場合はIssue番号を記載）
- [ ] 不要な `console.log` や `dbg!` が残っていないか
- [ ] エラーハンドリングが適切か（Rustでは`?`演算子、Vueでは`onErrorCaptured`でキャプチャされるか）

### フロントエンド固有
- [ ] `<script setup lang="ts">` パターンに従っているか
- [ ] Props定義が `defineProps<Props>()` パターンか
- [ ] ARIA属性が適切に設定されているか
- [ ] マジックナンバーがハードコードされていないか
- [ ] Composition APIのcomposableが適切に分離されているか

### バックエンド固有
- [ ] レイヤードアーキテクチャの依存方向が正しいか（kernel → adapter → api）
- [ ] `garde` によるバリデーションが入力に対して適用されているか
- [ ] パラメータバインドを使用しているか（`bind()` / `$1` 等）

### テスト
- [ ] 新機能にテストが追加されているか
- [ ] 既存テストが壊れていないか

## 出力形式

レビュー結果を以下の形式で報告:

```
## レビュー結果

### 問題点
| 重要度 | ファイル | 行 | 内容 |
|--------|----------|-----|------|
| 🔴 Critical | file.ts | 42 | 説明 |
| 🟡 High | file.rs | 100 | 説明 |
| 🟠 Medium | file.vue | 55 | 説明 |

### 良い点
- ...

### 提案
- ...
```

## 品質チェックの実行
レビュー完了後、以下を実行して結果を報告:
```bash
sampleapp local lint all
```
