# スコープ09: テストケースのコピーとCSV入出力

## 目的

新しいバージョンのテストケースを既存バージョンから引き継げるようにし、外部で作成したテストケースの取り込みと書き出しに対応する。

## 対象要件

- ユーザーはあるバージョンのテストスイート・テストケースを、同じプロダクトの別のバージョンへ一括コピーできる
- ユーザーはテストケースをCSVでインポートできる（取り込み前に内容と検証エラーを確認、エラーが1件でもあれば取り込まない、取り込み結果は下書き）
- ユーザーはテストケースをCSVでエクスポートできる（一覧の絞り込み条件を反映する）

## 前提スコープ

- 08 テストケースのレビュー・承認フロー

## 実施内容

### seed定義

| 種別 | 追加するもの |
| --- | --- |
| api_schemas | `CopyTestCasesRequest`（コピー元・コピー先バージョン、対象スイートの指定）、`CopyTestCasesResponseData`（コピー件数）、`ImportTestCasesPreviewResponseData`（行ごとの取り込み内容と検証エラー）、`ImportTestCasesRequest` |
| api_endpoints | `POST /v1/product_versions/{version_id}/test_cases/copy`、`POST /v1/product_versions/{version_id}/test_cases/import/preview`、`POST /v1/product_versions/{version_id}/test_cases/import`、`GET /v1/product_versions/{version_id}/test_cases/export` |
| errors | コピー元とコピー先が同一、別プロダクトのバージョンへのコピー、CSVの形式不正、必須項目の欠落、区分値の不正、ファイルサイズ・行数の上限超過 |
| pages | `TestCaseImport`（アップロードとプレビュー） |

### API

- `service/test_case_copy.rs`
  - コピー元バージョンのスイート階層を再帰的に複製し、対応するテストケースと手順を複製する
  - コピー元とコピー先が同一プロダクトであることを検証する
  - コピー先に同名スイートがある場合はその配下へマージせず、別スイートとして作成する
  - コピーされたテストケースのステータスは「下書き」にする
  - 1トランザクションで実行し、途中で失敗した場合は全件ロールバックする
- `service/test_case_import.rs`
  - CSVの列は「スイートパス / タイトル / 概要 / 前提条件 / 優先度 / 種別 / 想定所要時間 / 手順番号 / 操作内容 / 期待結果」とする
  - 行のグルーピングは「スイートパス」と「タイトル」の組み合わせが一致する連続行を1ケースの手順としてまとめる。スイートパスが異なれば同名タイトルでも別ケースとして扱う。組み合わせが一致しても連続していない（間に別ケースの行が挟まる）場合は別ケースとして扱い、行順どおりに手順を割り当てる
  - プレビューと取り込みで同じ検証ロジックを使う
  - 検証エラーが1件でもある場合は取り込みを行わない（行番号付きでエラーを返す）
  - スイートパスに対応するスイートが存在しない場合は作成する
  - 取り込んだケースはすべて「下書き」で登録する
- `service/test_case_export.rs`
  - 一覧と同じ絞り込み条件を受け取り、インポートと同じ列構成で出力する（往復できる形式にする）

### フロントエンド

- バージョン間コピーのダイアログ（コピー先バージョン、対象スイートの選択、件数の確認）
- CSVインポート画面（ファイル選択 → プレビュー表示 → 実行）
  - 検証エラーは行番号と項目名を添えて一覧表示する
- テストケース一覧にエクスポートボタンを追加する
- Storybookストーリーを作成する

## テスト

- コピー（階層構造・手順が保たれること、ステータスが下書きになること、別プロダクトへのコピーがエラーになること）
- インポートのプレビュー（正常系 / 必須項目の欠落 / 不正な区分値 / 手順番号の重複）
- 検証エラーがある場合に1件も登録されないこと
- 存在しないスイートパスが自動作成されること
- エクスポートしたCSVをそのままインポートできること

## 完了条件

- バージョン間コピーとCSVのインポート・エクスポートが動作する
- API統合テストとフロントエンドのlint・type-checkが通る

## 判断が必要な点

- **同期処理で実装する**: 取り込みは同期処理とし、行数の上限（例: 1000行）とファイルサイズの上限を設けてエラーにする。非同期ジョブ基盤は導入しない。
- **文字コードと改行**: UTF-8（BOM付きも受け付ける）とし、出力はBOM付きUTF-8にする。Excelでの文字化けを避けるため。
- **既存ケースの更新**: インポートは新規追加のみとし、既存ケースの更新やIDによる突き合わせは行わない（同一タイトルのケースは重複して登録される）。
